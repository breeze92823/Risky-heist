# Risky Heist

## Repos
- Frontend (this repo): `C:\ThreeJS\Risky-heist\Risky-heist`
- Backend: `C:\ThreeJS\Risky-heist\Risky-heist-backend` (Colyseus + MongoDB game server, see its CLAUDE.md for the message/save contract). `src/net.js` connects to it: a signed-in player's progress is loaded from and mirrored to the server (`game.js` `snapshot()` / `hydrate()` / `onSave()`), and nothing is ever stored in the browser (no `localStorage` save: a guest or offline session starts fresh every load; a new account's first save is the state played so far). Guests are never saved server-side. A room holds 6 players and each owns one of the hub's 6 base plots (`BASE.positions`): the server assigns the plot on join, `game.js` `setMyBase` moves your base, its tools and its interaction targets there (`bases[]` = one live `createBase` per plot, `base` = yours), and `setRoster` puts the other owners' names and loot on their plots (`net.js` polls the roster twice a second and sends `setBase` when your slots change). Offline you keep plot `BASE.player`. Other players' avatars are not drawn yet (pose relay and leaderboards exist on the server only).
- Reference game for Bloxity patterns: `C:\ThreeJS\Clean-leaves-for-loot\Clean-leaves-for-loot` (the avatar/ and bloxity.js code here was ported from it).

## The game
A heist tycoon. The player rides a zipline from the HUB across a river to a 50-floor tower, smashes the glass entrance, steals treasures (carry slots limit how many), climbs the stairs and breaks each floor's door (hit points; tools set damage) to reach richer floors (x2 ... x5 luck), leaves through the floor's glass exit to its balcony and ziplines home. Loot placed on base slots earns $/s into a green collector pad (walk over it) and adds Luck to every future roll. "Jail Chance" rises on the heist bank (faster higher up); at 100% the player is busted and loses carried loot. Everything is bought with cash; never add premium-currency purchases (see the root CLAUDE.md). Rebirth (`REBIRTH`) spends all cash once you have the cost for a permanent cash multiplier on base income and sales. Daily Gifts (`DAILY`): one more day unlocks every 24 h of play, 7 rewards (cash + items, incl. the `exclusive` Golden Trophy and Nuclear Barrel that are never rolled in the tower); Claim All costs cash (worth x 1.15). All windows share one layout (`hud.js` `openPanel({ title, icon, color, body, wide })`: accent border, icon title tab, red X).

Floors are generated in config (`FLOOR_COUNT`, `FLOORS`, `DOORS`, `FLOOR_ODDS`): rarity odds are a bell curve over the 9 rarities whose centre climbs with the floor, and luck shifts it up by `LUCK_SHIFT * log2(1 + luck/100)` tiers. The hub zipline always lands on the ground floor (no floor picker); you climb by stairs and doors, and can zipline home from any floor's balcony. `building.js` streams floor contents: only the player's floor +-1 (or a forced zipline destination, `keepLive`) has treasure models, labels, signs, HP doors and balcony pads in the scene. Wall colliders only split at doors (windows are solid) to keep the collider count low.

All game data (layout, building, zipline, bases, stalls, rarities, treasures, floors, upgrades, tools, jail, boosts, timed spawns) is in `src/config.js` under "Risky Heist: game data". Game code lives in `src/heist/`:
- `game.js` rules + save state, zipline rides (`player.js` `setDriver`), heist flow (restock + door reset on every trip to the tower), jail heat and busts, base income/collect, purchases, panels, the arm-pose overrides. Dev: `__game.game.debug`.
- `hub.js` hub island, river, cliffs, foliage, dock + towers, stalls, billboards, the far bank yard. `building.js` the tower (walls with openings, stairs + ramp colliders, stairwells with HP doors, glass doors, balconies, themed interiors, treasure spots, floor-following lights). `base.js` base shell (baked, one per plot) + each plot's live parts (`createBase`: owner sign, loot; yours also has info labels, collector cash, stats sign and the upgrade board via `setMine`).
- `models.js` 23 procedural treasure models + HUD thumbnails. `fx.js` pooled particles/debris/rings/floating text/shake. `sfx.js` procedural WebAudio sound (no files; levels and ranges in config `AUDIO`): HUD buttons click / hover / disabled via `hud.js` `button()`, panel open/close, toasts, banners, interaction prompts; cash register, coins, glass, wood doors, steal sparkle by rarity, zipline trolley; footsteps per surface + jump/land and ambience (wind by height, river by distance, hub birds, tower room tone, walls muffle outdoors) from `sfx.frame()` each frame (listener = camera); police cruisers as 3D sources (engine, roof siren, radio chatter) from `hub.police`, a far siren layer following Jail Chance (wail, yelp from `AUDIO.siren.yelpAt`), searchlight alarm beeps, star alerts, Stop Police sleep/wake and the bust (whoop, whistle, handcuffs). Overlap control: one-shots count against a voice budget (`AUDIO.voices`, extra ones are dropped), every named sound has a minimum re-trigger gap (`GAPS`; e.g. a collector pad credits every frame) and minor UI blips yield to major sounds; a limiter sits after the bus compressor. `music.js` adaptive background music on the same context (config `MUSIC`): an original spy-jazz loop arranged five ways (lounge in the hub, stealth on the heist bank, tension / chase / climax as the Jail Chance passes `MUSIC.heat`), layers crossfade and the tempo glides per step, steps up hit a crash + timpani, down only after 3 s; stingers on a bust (loop stops until respawn) and an escape with loot (`music.stinger`). Settings window (`hud.js` left-column Settings button, `game.js` `openSettings`): Music and Sound Effects ON/OFF, saved as `state.prefs { music, sfx }` with the progress (the backend sanitizes `prefs`). `interact.js` E / tap prompts (hold to repeat). `hud.js` + `hud.css` DOM HUD and panels. `kit.js` world-UV boxes, materials, colliders, labels. `paint.js` canvas painters.
- Static scenery is merged with `bake.js`; sprites and anything animated stay live.

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Bloxity integrations (`BLOXITY_CODE_METADATA.md` lists what is done and what is not applicable)
All SDK calls are in `src/bloxity.js` (feature-detected, never throw). Environment URLs come from `SDK.environment()` (`apiUrl()` / `staticUrl()`), never hardcoded or guessed from the hostname (`avatar/cdn.js` too). The server verifies the player's `getToken()`; the client sends no account id (`net.js`). Settings: `master_volume` (-> `sfx.js` `setVolume`), `graphics_quality`, `camera_sensitivity`, `show_fps` (`fps.js`), `fullscreen`. Emotes: `registerFeature('emotes')`, `avatar/emotes.js` plays the portal's catalogue clips on the rig until you move. Chat bubbles over your own character (`main.js`). Death screen on a bust (`game.js` `bust()` + `hud.deathPrompt`). Ads: ad breaks pause the loop and mute (`main.js`), screen ads (`AD_SCREENS`: `gameplay` off, `panel` for HUD windows), a "Free Cash" rewarded ad (`REWARDED_AD`, cash only, verified by the server). Leaderboards declared in `LEADERBOARDS` (the server reports the scores). Rooms: `updateRoom`, `playerJoined` / `playerInRoom`, `?roomId=` launch join (`net.js`). Not done: Gems (never sold here).

## Other players (`avatar/remotePlayers.js`)
Everyone else in the room is drawn as a character. `net.js` `sendPose` (~`NET.poseHz`/s, only on change: x, y, z, yaw, speed, grounded), `syncAvatar` (`{ equipped, proportions }` JSON: ids only, never URLs) and `sendEmote` feed the server roster (`pose` / `setAvatar` / `emote`); `main.js` calls `remotes.update(dt, net.players, net.sessionId)` every frame. Each `Remote` = a character + the same procedural animator (driven by the reported speed / grounded and the vertical speed it derives) + its own `createEmotePlayer()` (`avatar/emotes.js`) + a name tag; its pose eases toward the last report (`NET.remoteLerp`, snaps beyond `NET.remoteSnap`). Their look is rebuilt with `loader.js` after `parseLook` strips anything but known slot keys and slug-shaped ids (an id ends up in an asset URL, so never trust it). Chat: Boxity's `m.userId` is matched to the roster's server-verified `userId` (`remotes.say`). Body state travels with the pose (`game.bodyState()`: `carry` = best carried treasure id, `riding`, `swing`) and is drawn with the same code as the local player's (`heist/bodyFx.js`: `applyArmPose`, `makeTrolley`, `swingAmount`): loot floating over the head (name tag moves up), arms up + legs tucked + a trolley on the cable while riding, the arm swing while hitting a door. Draw range: only players within `NET.remoteRange` (70 m, +`remoteRangeSlack` hysteresis) are drawn, animated and have their look loaded; far ones are hidden and snap into place on return.

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, ground slab + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `net.js`: Colyseus link (`initNet(game)` from `main.js`). Resolves the endpoint (`SERVER_URL` from `config.js`, else the Bloxity matchmaker via `bloxity.resolveServerEndpoint`), joins room `world`, hydrates the game on `progress`, sends `saveProgress` (<= 1 per `NET.saveEvery` s, flushed when the tab hides/closes), re-sends `identify` on sign-in/out. Never throws; unreachable server = offline play, retried every `NET.retry` s. A reconnect within a page keeps the local state (newer than the server's).
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Ground**: the land is built by `heist/hub.js`; `world.js` `createWorld(scene)` still supplies the sea (the river surface at `WATER.level`) and clouds. `buildGround`/`landColliders` (the old sand slab) are unused.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, E interact (hold on doors; tap the prompt on touch), mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
